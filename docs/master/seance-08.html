1

Installer Python et VS Code

20 minutes · les deux briques de base

Deux logiciels, dans cet ordre. Python exécute le code, VS Code est l'éditeur dans lequel tu l'écris. Ce sont deux choses séparées, et c'est la source de confusion numéro un des débutants.

🐛 La case à cocher qui coûte une heure

Sur Windows, l'installateur Python propose « Add python.exe to PATH » en tout petit, en bas de la première fenêtre. Elle n'est pas cochée par défaut.

Si tu l'oublies, ton terminal répondra python n'est pas reconnu à chaque commande, et rien d'autre ne marchera. Coche-la. Si c'est déjà raté, réinstalle : c'est plus rapide que de réparer.

🎙️ Les trois extensions VS Code, et pas une de plus

Dans l'onglet Extensions (l'icône en forme de blocs) : Python, Pylance et Jupyter, toutes trois publiées par Microsoft.

Résiste aux dizaines d'autres. Un éditeur surchargé d'extensions devient lent et imprévisible, et tu passeras plus de temps à le configurer qu'à analyser.

2

Pourquoi un environnement par projet

20 minutes · l'environnement virtuel

Imagine deux missions. La première utilise pandas 1.5, la seconde exige pandas 2.2, qui a changé le comportement de certaines fonctions. Une seule installation de Python sur ta machine ne peut pas satisfaire les deux.

Un environnement virtuel est un dossier qui contient sa propre copie de Python et ses propres bibliothèques. Un par projet. Ils s'ignorent complètement.

$ cd Documents/analyse-elections # creer l'environnement (une seule fois par projet) $ python -m venv .venv # l'activer (a chaque fois qu'on ouvre un terminal) $ .venv\Scripts\activate ← Windows $ source .venv/bin/activate ← macOS (.venv) $ ← le prefixe confirme que c'est actif
💡 Le préfixe (.venv) est ton seul témoin

Tant qu'il n'apparaît pas au début de ta ligne de commande, tu travailles dans le Python global, et tout ce que tu installes part au mauvais endroit.

C'est la cause de 80 % des « ça marchait hier ». Prends le réflexe : avant toute commande pip, regarde si le préfixe est là.

🌍 Pourquoi ça compte vraiment en entreprise

Le vrai problème n'est pas ton confort, c'est la reproductibilité. Une analyse qui ne tourne que sur ta machine n'a aucune valeur : personne ne peut la vérifier, la reprendre, ni la faire tourner l'an prochain.

L'environnement isolé, plus le fichier requirements.txt, c'est ce qui permet à un collègue de reproduire ton résultat exactement. En finance et en conseil, un chiffre non reproductible est un chiffre mort.

3

Installer les bibliothèques

15 minutes · pip et requirements.txt
(.venv) $ pip install pandas matplotlib jupyter # verifier ce qui est installe (.venv) $ pip list # figer les versions, pour que quelqu'un d'autre reproduise (.venv) $ pip freeze > requirements.txt # et pour reinstaller a l'identique, ailleurs (.venv) $ pip install -r requirements.txt
🎙️ Le fichier qui te sauvera

requirements.txt liste les bibliothèques avec leurs numéros de version exacts. C'est le seul moyen de retrouver dans six mois l'environnement qui produisait ton chiffre.

Fais-le générer maintenant, même s'il n'y a que trois lignes dedans. L'habitude compte plus que le contenu.

Ton premier notebook

25 minutes · le format de travail de l'analyse

Un notebook mélange du code, ses résultats et du texte, dans un document unique. C'est le format de travail réel de la finance et du conseil : on y raisonne par étapes, chaque cellule s'exécute indépendamment, et le résultat reste affiché sous le code qui l'a produit.

  1. Dans VS Code : Fichier → Nouveau fichier → Jupyter Notebook
  2. Enregistre-le sous analyse.ipynb dans ton dossier de projet
  3. En haut à droite, clique sur Select Kernel et choisis l'interpréteur qui contient .venv

🎯 Le contrôle qui valide toute la séance

La première ligne affiche le chemin de l'interpréteur utilisé. Il doit contenir .venv.

S'il pointe ailleurs — Program Files, anaconda3, /usr/bin — le notebook n'utilise pas ton environnement, et tes installations n'y seront pas. Reprends le choix du kernel.

🎙️ Le piège du notebook, à montrer tout de suite

Les cellules s'exécutent dans l'ordre où tu cliques, pas dans l'ordre où elles sont écrites. On peut donc obtenir un notebook qui affiche des résultats justes et qui, relancé de haut en bas, plante ou donne autre chose.

Le réflexe professionnel : avant de partager quoi que ce soit, Restart & Run All. Si ça ne passe pas, ton analyse n'est pas reproductible, donc elle n'existe pas.
